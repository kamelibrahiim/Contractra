## 3. ⭐ إعادة توليد النسخة التفاعلية

### 3.1 الأمر

```
cd docs
python3 generate-html.py
```

**بلا وسائط** يستخدم المولّد الافتراضيات:

| البند | القيمة الافتراضية |
|---|---|
| المدخل | `system-specification-and-team-reference-ar.md` |
| المخرج | `system-specification-and-team-reference-ar.html` |

**ولتوليد ملف آخر:**

```
python3 generate-html.py <input.md> <output.html>
```

### 3.1.1 ⭐ وثيقة تصميم قاعدة البيانات — أمران بالترتيب

```
cd docs
python3 generate-erd.py  database-design-ar.md                          ← أولًا: الرسم
python3 generate-html.py database-design-ar.md database-design-ar.html  ← ثانيًا: الصفحة
```

> ⭐ **الترتيب ملزم:** **الصفحة تدمج الرسم الموجود على القرص.** **وتوليد الصفحة وحدها بعد تعديل المخطط يعرض المصدر النصي بدل الرسم** — ⛔ **ولا يكسر شيئًا لكنه لا يُحدِّث الصورة.**

| البند | القيمة |
|---|---|
| **متطلب `generate-erd.py`** | ⭐ **Graphviz (الأمر `dot`)** — `apt install graphviz` · `brew install graphviz` · `choco install graphviz` |
| ⭐ **متى يُطلب** | **وقت التوليد فقط** — ⛔ **والصفحة الناتجة لا تحتاج شيئًا: الـSVG مدموج داخلها** |
| **إن لم يكن مثبَّتًا** | ⭐ **يتوقف برسالة واضحة ⛔ ولا يحذف أي رسم سابق** — فتبقى الصفحة سليمة |
| **كيف يعرف المولّد أي رسم لأي مخطط** | ⭐ **ببصمة نص المخطط نفسه** في `erd-render-map.json` — **فتعديل المخطط يُبطل الرسم القديم تلقائيًا ولا تُعرض صورة قديمة خطأً** |

## 4. ⭐ ما يفعله المولّد بالضبط

### 4.1 التحويلات المدعومة

| عنصر Markdown | ⟹ HTML | ملاحظة |
|---|---|---|
| `## N. عنوان` | ⭐ **عنوان لوحة** `panel-title` **داخل التبويب الذي يضمّ القسم N** | ⭐ **الخريطة في §4.5** |
| `### عنوان` **يليه جدول أو قائمة أو كتلة كود** | ⭐ **ترويسة بطاقة** `card-header` — **نقطة ملوّنة · العنوان · عدّاد الصفوف** | ⭐ **بمعرّف ثابت — فيدخل فهرس التبويب** |
| `### عنوان` **يليه نص** | **عنوان فرعي بحدّ بنفسجي جانبي** `section-title` | — |
| `#### … ######` | **عنوان فرعي أصغر** `sub-title` — أو **ترويسة بطاقة** بحسب ما يليه | — |
| `\| جدول \|` | ⭐ **بطاقة** تحوي `<table>` في حاوية قابلة للتمرير | ⭐ **ورأس الجدول ثابت عند التمرير · وعدد الصفوف في الترويسة** |
| ` ```mermaid ` | ⭐ **كتلة مصدر مُسمّاة «مخطط Mermaid — المصدر النصي»** | ⭐ **§4.3** |
| ` ```gherkin ` | ⭐ **بطاقة كود مُسمّاة «معيار قبول — Given / When / Then»** | لمعايير القبول |
| ` ``` ` عامة | **بطاقة كود مُسمّاة «مقتطف»** | باتجاه LTR |
| `> اقتباس` | ⭐ **صندوق ملوّن** `info-box` — **ولونه يُشتق من رمز السطر نفسه** | ⛔ **danger** · ⚠️ **warn** · ⭐ **tech** · ✅ **ok** · وإلا **info** |
| `- قائمة` · `1. قائمة` | ⭐ **بطاقة قائمة** `rule-list` — **وبترويسة إن سبقها عنوان** | — |
| `**عريض**` · `*مائل*` · `~~مشطوب~~` | `<strong>` · `<em>` · `<del>` | — |
| `` `كود` `` | `<code>` | **باتجاه LTR داخل نص عربي** |
| `[نص](رابط)` | `<a>` | — |
| `---` | `<hr>` | — |

### 4.2 ⭐ الشارات — مشتقة من رموز Markdown نفسها

⭐ **المولّد لا يخترع شارة** — بل **يلفّ الرموز الموجودة في Markdown** بعنصر يحمل وصفًا يظهر عند التمرير:

| الرمز | الشارة | الوصف |
|---|---|---|
| 🟢 | `b-confirmed` | مؤكدة |
| 🔵 | `b-proposed` | مقترح |
| 🟡 | `b-open` | قرار مفتوح |
| ⚪ | `b-assumption` | افتراض |
| 📊 | `b-evidence` | دليل تاريخي |
| 🔧 | `b-migration` | مسألة ترحيل |
| 🔮 | `b-future` | نطاق مستقبلي |
| ⛔ | `b-forbidden` | ممنوع |
| ⭐ | `b-critical` | حرج |
| ⚡ | `b-idempotent` | منع تكرار |
| 🔒 | `b-sensitive` | حساس |
| ⚠️ | `b-warning` | تنبيه |
| ✅ | `b-ok` | مستوفى |
| ❌ | `b-no` | غير مستوفى |

> ⭐ **ولهذا: لإضافة شارة، أضف رمزها في Markdown — ⛔ لا تعدّل HTML.**

### 4.3 ⭐ مخططات Mermaid — قرار معلَن

| البند | القرار |
|---|---|
| **المشكلة** | ⭐ **عرض Mermaid كصورة يتطلب محرّك رسم** — و**تحميله من CDN مخالف للقاعدة 4 في §1** |
| **القرار** | ⭐ **يُعرض المصدر النصي للمخطط داخل كتلة مُسمّاة** |
| **لماذا مقبول** | ⭐ **كل مخطط في الوثيقة مصحوب بشرح عربي نصي يليه** — **فالمعنى لا يضيع** |
| **البديل عند الحاجة** | ⭐ **نسخ المصدر ولصقه في أي محرّر Mermaid** للحصول على الصورة |
| **إن أُريد الرسم داخل الملف** | ⭐ **الشرط: تضمين محرّك الرسم داخل الملف نفسه — ⛔ لا من CDN** · و**هذا يزيد حجم الملف كثيرًا ويحتاج قرارًا صريحًا** |

### 4.4 ⭐ القدرات التفاعلية

| القدرة | كيف تعمل |
|---|---|
| ⭐ **تبويبات** | **أحد عشر تبويبًا** يعرض كلٌّ منها **لوحة واحدة** — ⭐ **فلا تمرير طويل عبر 35 قسمًا** |
| ⭐ **فهرس التبويب** | **زر «الفهرس» أسفل الصفحة** — **يُبنى تلقائيًا للتبويب المفتوح** من عناوين اللوحات والبطاقات |
| ⭐ **بحث في كل التبويبات** | **مربع البحث في الترويسة** — **يميّز كل المطابقات في كل التبويبات** · ⭐ **ويعرض عدّاد المطابقات بجانب اسم كل تبويب** · **ويقفز إلى أول مطابقة في التبويب المفتوح** |
| **مسح البحث** | **إفراغ المربع** يزيل التمييز ويعيد العدّادات إلى عدد الأقسام |
| ⭐ **روابط داخلية** | **كل عنوان — لوحةً كان أو بطاقة — له معرّف ثابت** · **و`#اسم-التبويب` في الرابط يفتح ذلك التبويب مباشرة** |
| ⭐ **ترويسة لاصقة** | **الترويسة وشريط التبويبات ملتصقان أعلى الصفحة** — ⭐ **وارتفاعهما يُقاس بـJS ولا يُثبَّت برقم**، فلا يختفي عنوان خلفهما |
| ⭐ **طباعة** | ⭐ **تفتح كل التبويبات دفعةً واحدة** · **وتزيل الشريط والأزرار والتمييز** · **A4 بهوامش مضبوطة** · **وتمنع قص البطاقات والصفوف** |
| ⭐ **الوضع الداكن** | **تلقائي بحسب إعداد النظام** |
| ⭐ **RTL كامل** | **بخصائص منطقية** (`border-inline-start` · `margin-inline-start`) — والكود وحده بـLTR لأنه إنجليزي |
| ⭐ **الاستجابة** | **شريط التبويبات يلتف على أكثر من سطر** · **والجداول تتمرّر أفقيًا داخل بطاقاتها** |
